FreeLLMAPI 在飞牛 FNOS Docker 上的安装指南

将 FreeLLMAPI 部署为局域网内的多供应商 LLM 聚合 API 网关。推荐数据目录：/vol1/1000/docker/freellmapi。

目录 1. 部署前准备 2. 创建目录 3. 生成加密密钥 4. Compose 配置 5. 启动容器 6. 首次配置 7. 客户端接入 8. 维护命令 9. 常见问题 10. 安全建议

FreeLLMAPI 是普通 Web/API 容器，不需要特权模式、USB 设备映射或 host 网络。官方 Compose 默认仅绑定本机 127.0.0.1:3001；若要从局域网浏览器访问，需要绑定 0.0.0.0。

安全提示：不要通过路由器端口映射将 3001 直接暴露到公网。远程访问应采用 VPN/Tailscale 或带 HTTPS 和访问控制的反向代理。

官方资料：安装文档 · 官方 Docker Compose · 中文 README

1. 部署前准备

  • FNOS 已安装 Docker / Container Manager，并且可以 SSH 登录
  • Docker Compose v2 可用
  • NAS 可访问 GitHub Container Registry（ghcr.io）和后续接入的模型供应商 API
  • 计划通过局域网地址访问，例如 http://FNOS_IP:3001

如果当前 SSH 账号拥有管理员权限，进入 root shell：

sudo -i

运行只读检查：

id
uname -m
docker version
docker compose version
docker ps

预期：架构为 x86_64 或 aarch64、Docker Server 正常、Compose 为 v2，且 docker ps 无权限报错。

2. 创建部署目录

本方案使用绑定目录保存数据，方便在 FNOS 上备份、迁移和检查。

sudo -i

mkdir -p /vol1/1000/docker/freellmapi/data
cd /vol1/1000/docker/freellmapi

pwd
ls -ld /vol1/1000/docker/freellmapi /vol1/1000/docker/freellmapi/data

chmod 755 /vol1/1000/docker/freellmapi
chmod 755 /vol1/1000/docker/freellmapi/data
不要一开始就设置 777。如日志显示数据目录权限不足，再按后文的针对性排障方式处理。

3. 生成加密密钥

ENCRYPTION_KEY 用于加密保存你填写的 Provider API Key。生成一次后应保存到密码管理器，且部署后不要随意变更。

openssl rand -hex 32

创建环境变量文件：

nano /vol1/1000/docker/freellmapi/.env

将下列内容粘贴进去，并替换加密密钥：

# 仅用于局域网访问。不要在路由器上把此端口直接转发到公网。
HOST_BIND=0.0.0.0

# FNOS 宿主机暴露的端口
PORT=3001

# 用于加密保存 Provider API Key；部署后不要更改
ENCRYPTION_KEY=请替换为你刚生成的64位随机字符串

# 可选：如果 FNOS 需要通过宿主机代理访问 Google/GitHub/海外 API，取消注释并改为实际端口。
# 注意：容器中 127.0.0.1 指向容器自身，不能代表 FNOS 宿主机。
# PROXY_URL=http://host.docker.internal:7890
# 或：
# PROXY_URL=socks5h://host.docker.internal:7890

保存 nano 文件：按 Ctrl + O、回车，再按 Ctrl + X。之后限制文件权限：

chmod 600 /vol1/1000/docker/freellmapi/.env
若使用 Clash、mihomo、sing-box 等宿主机代理，容器应该通过 host.docker.internal 访问，而不是使用 127.0.0.1。宿主机代理也必须允许 Docker bridge 网络访问。

4. 创建 Docker Compose 文件

nano /vol1/1000/docker/freellmapi/docker-compose.yml

完整粘贴以下配置：

services:
  freellmapi:
    image: ghcr.io/tashfeenahmed/freellmapi:latest
    container_name: freellmapi
    restart: unless-stopped

    env_file:
      - .env

    environment:
      NODE_ENV: production
      PORT: 3001

    ports:
      - "${HOST_BIND:-127.0.0.1}:${PORT:-3001}:3001"

    volumes:
      - ./data:/app/server/data

    extra_hosts:
      - "host.docker.internal:host-gateway"

    healthcheck:
      test:
        [
          "CMD",
          "node",
          "-e",
          "fetch('http://127.0.0.1:3001/api/ping').then((res) => { if (!res.ok) process.exit(1); }).catch(() => process.exit(1));"
        ]
      interval: 30s
      timeout: 5s
      start_period: 20s
      retries: 3

验证 Compose 配置：

cd /vol1/1000/docker/freellmapi
docker compose config

确认显示端口映射到 0.0.0.0:3001，且数据卷对应：

/vol1/1000/docker/freellmapi/data:/app/server/data

5. 启动容器

cd /vol1/1000/docker/freellmapi

docker compose pull
docker compose up -d
docker compose ps

查看启动日志：

docker compose logs --tail=150 freellmapi

检查健康状态：

docker inspect --format '{{.State.Status}} | health={{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}}' freellmapi

理想输出为：

running | health=healthy

在 FNOS 本机检查服务：

curl -i http://127.0.0.1:3001/api/ping

# 如果没有 curl：
wget -qO- http://127.0.0.1:3001/api/ping

6. 首次访问与配置

在同一局域网设备的浏览器中打开：

http://你的FNOS局域网IP:3001

# 示例：
http://192.168.1.20:3001
  1. 完成管理端的初始设置
  2. 进入 Keys 或 Providers 页面
  3. 先添加一到两个上游 Provider Key 测试
  4. 优先使用已有账号且网络可达的 Provider，如 Gemini、Groq、OpenRouter、GitHub Models
  5. 在 Models、Routes 或 Fallback 中启用模型并设置候补链
  6. 为 OpenWebUI、Cherry Studio、脚本或自建应用创建 FreeLLMAPI 统一客户端 Key

客户端的连接地址应为：

http://FNOS_IP:3001/v1
客户端应使用 FreeLLMAPI 创建的统一 Key，不能填入 Gemini、Groq 等真实上游 Provider Key。

7. OpenAI 兼容客户端接入

API 类型：OpenAI Compatible
Base URL：http://192.168.1.20:3001/v1
API Key：在 FreeLLMAPI 中创建的统一客户端 Key
模型：在 FreeLLMAPI 后台已启用的模型 ID

使用 curl 测试。请替换实际 NAS 地址、统一 Key 和模型 ID：

curl http://192.168.1.20:3001/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer freellmapi-替换为你的统一客户端Key" \
  -d '{
    "model": "替换为后台显示的模型ID",
    "messages": [
      {
        "role": "user",
        "content": "你好，请用一句话说明你是谁。"
      }
    ]
  }'
不要把真实 freellmapi-...、sk-...、AIza...、gsk_... 或 fla_... Key 发送到聊天、截图、公开仓库、前端代码或日志中。

9. FNOS 常见问题

容器启动但网页打不开

cd /vol1/1000/docker/freellmapi
docker compose ps
docker compose logs --tail=200 freellmapi
curl -i http://127.0.0.1:3001/api/ping
ss -lntp | grep ':3001' || true
  • NAS 本机 curl 成功、局域网打不开：确认 .env 有 HOST_BIND=0.0.0.0，然后执行：docker compose up -d --force-recreate
  • NAS 本机也打不开：优先检查 docker compose logs --tail=200 freellmapi
  • 端口被占用：将 .env 内的 PORT=3001 改为 PORT=13001，再执行 docker compose up -d --force-recreate

日志出现 Permission denied

ls -ld /vol1/1000/docker/freellmapi/data

chmod -R u+rwX,g+rwX /vol1/1000/docker/freellmapi/data
docker compose restart

若依旧报错，收集日志以便按容器实际 UID/GID 调整目录属主：

docker compose logs --tail=100 freellmapi

容器不能访问 Gemini/Groq 等海外服务

如果宿主机代理监听 7890，编辑 .env：

PROXY_URL=http://host.docker.internal:7890

# 或 SOCKS5：
PROXY_URL=socks5h://host.docker.internal:7890

然后重新创建容器：

cd /vol1/1000/docker/freellmapi
docker compose up -d --force-recreate
docker compose logs --tail=100 freellmapi

同时确认代理没有只绑定 127.0.0.1，且允许 Docker bridge 网段连接其入站端口。

10. 安全建议

  • 优先用于家庭局域网，不要直接公开端口 3001
  • 客户端只使用 FreeLLMAPI 统一 Key，不要使用真实 Provider Key
  • .env 保持 600 权限，不提交到 Git
  • 迁移或备份时必须同时保留 data 和其中的 ENCRYPTION_KEY
  • 需要远程访问时，优先 VPN/Tailscale；使用反代则应开启 HTTPS，附加 Cloudflare Access、Basic Auth 或 IP 白名单
  • Premium 的 fla_... License Key 仅用于实时 catalog 授权，不会替代上游 Provider API Key

总结

FreeLLMAPI 可作为 FNOS 上的轻量 Docker 服务运行：你在 NAS 内部保存并管理不同 Provider 的 API Key，对局域网客户端仅暴露一个 OpenAI 兼容的 /v1 API 地址和统一客户端 Key。它负责聚合、路由与故障转移，但不会提供第三方模型余额，也不会绕过上游服务商的额度和使用规则。

本文部署路径统一为：/vol1/1000/docker/freellmapi。
